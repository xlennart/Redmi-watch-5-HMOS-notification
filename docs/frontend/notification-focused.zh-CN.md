# 通知功能界面与使用流程

2026-10-07 按用户最新要求收敛到通知。此文档取代此前“三页导航”和健康、运动主页面规划；历史原型仅保留作设计参考。当前应用采用现有 ArkUI V1 与语义配色，没有扩展健康、音乐或资源采集。

## 页面

- 通知主页面：紧凑设备名称、转发状态、主要启停动作、系统授权入口、发送测试通知及问题排查。移除大幅设备插画、底部三页导航、未来功能入口、累计计数与重复技术说明。不展开授权应用清单。
- 设置：管理已选手表与本机认证材料、刷新状态、高级订阅及材料删除。敏感操作继续有明确确认；已有材料不会因重新导入失败而删除。
- 初始化：只补齐缺少的设备、材料或权限。日志导入作为可用路线，账号同步保留在认证步骤。完成后可明确开启转发并回到主页面。
- 问题排查：普通测试与授权入口在前，消息通道、震动、手表通知类别修改、累计计数、错误与图标阶段在后。

## 测试流程

用户点“发送测试通知”。转发开启或当前会话仍活动时，先说明将暂停，并明确由用户在测试后继续转发。确认后写入停止配置、等待实际会话释放，再发送固定测试。失败、取消或未确认关闭时不能开始另一诊断，也不会自动重新开启转发。

测试结束询问是否实际看到了“腕间通知测试”；震动测试单独询问是否短震两次。传输收包与人工确认独立。若此前暂停了转发，显示“继续通知转发”按钮；恢复时重新校验系统授权与当前配对。导航不会把历史收包变成当前在线，取消中的旧回调不能覆盖新测试状态。

从旧版本恢复的目标先迁移到私有设备选择记录，再停转发，避免旧配置清空后丢失选择。密钥、账号会话、原始消息与设备地址不进入页面。

## 图标证据

用户反馈手表依然显示默认图标，因此本轮不记录“图标已解决”。新增当前来源主动协商、PNG 编码、资源读取回退与具体失败阶段；详见 `docs/notification-icons.zh-CN.md`。本轮继续按用户约定仅编译签名和覆盖安装，安装后不操作手机检查。
