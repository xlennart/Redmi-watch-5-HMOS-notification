# 腕间通知前端设计基线 v0.2

交付日期：2026-10-07。目标：Mate 70 Pro 优享版、原生 HarmonyOS / API 26、ArkUI V1；当前协议目标 Redmi Watch 5。此目录包含独立设计产物，不修改原仓库的页面、服务、协议、构建或测试。

## 本轮原生交付

已新增 native-preview 独立原生 ArkUI V1 项目，API 26 完整清理编译成功。包含今日 / 设备 / 通知、初始化、诊断、十三种评审情景、原生对话框、深色与大字控制。业务由模拟 ViewModel 驱动，尚未接入原仓库服务。源码包为 wristnotifications-arkui-preview.zip；未签名 HAP 和构建记录同时提供。

根据用户最新要求，不再安排虚拟机验收；原生界面、系统主题/字号、安全区域、无障碍与通知链路留待后续一并实机检验。HTML 保留为离线辅助评审产物。

## 先评审什么

打开 wristnotifications-prototype.html，可离线运行，无外部字体、图片、脚本或网络请求。顶部“评审情景”不是产品界面，用来切换十三类状态；“深色”和“大字 125%”用来检查适配。所有互动、计数、来源、时刻、文件选取与账号流程都明确标注为模拟，刷新即复位。

先看“今日”的状态与启停，再走“设备初始化”，最后查看“诊断与验证”。初始化完成不自动启动转发。原型模拟操作不产生新的真机证据。

本轮遵循项目内 harmonyos-frontend-design 技能的视觉、ArkUI 映射和评审规范。色彩、尺寸、断点是项目建议，不是官方规格；CSS px/rem 不直接等同 ArkUI vp/fp。

## 信息架构

| 层级 | 页面 | 日常任务与入口 |
| --- | --- | --- |
| 一级 | 今日 | 当前设备、持久转发开关、需处理的问题、权限与认证准备、累计统计摘要 |
| 一级 | 设备 | 设备基本状态、认证材料与权限、初始化、账号路线、诊断入口、高级管理 |
| 一级 | 通知 | 开启/停止转发、只读系统授权来源清单、打开系统授权、本轮行为规则 |
| 二级 | 初始化引导 | 选择已配对设备 → 准备认证 → 允许通知 → 完成设置 |
| 二级 | 诊断与验证 | 消息通道、固定提醒、震动、显式修改通知类别、计数与安全技术详情 |
| 浮层 | 确认 / 结果 | 切换设备前停转发、删除材料、停订阅、修改类别；导入/账号错误及恢复 |

首页保留一个主要行动。状态问题优先给可执行的恢复入口。账号失败只放在账号/材料路线；已有日志认证材料可继续通知功能。高级入口收纳 AuthKey 管理语义、协议阶段、错误码和诊断，不把技术流程留在日常首页。

音乐、健康、资源入口能查看诚实的能力说明。它们不提供假的操作、进度或数据。长期可扩展到功能详情，不在本轮预先铺设空的五个主导航页。

## 状态表达

持久开关、授权快照、系统配对、消息会话、传输证据五者独立。当前实现每条消息按需建立连接并重新认证，临时会话关闭后状态应回到“本次状态未知 / 按需连接”。HFP 通话连接、配对记录、认证材料存在、过去 ACK 都不能转换成“手表当前在线”。

| 状态 | 主要文案 | 主行动 / 可恢复路径 |
| --- | --- | --- |
| 首次无设备 | 还没有选择手表 | 开始初始化；从系统配对候选中选择，不自动配对 |
| 有设备无材料 | 还差一步：准备认证材料 | 进入日志导入；账号路线“待验证” |
| 正在连接 / 认证 | 消息通道正在连接 / 认证 | 转发开关仍独立；允许停止当前转发 |
| 初始化完成且停止 | 通知转发已停止 | 开启通知转发，保留授权 |
| 开关开启等待通知 | 通知转发已开启 | 停止；解释按需连接，不显示持续在线 |
| 断线 / 最近发送失败 | 转发已开启 · 等待恢复 | 开关保留，查看诊断；失败消息不盲目重发 |
| 全局通知权限撤销 | 转发已开启 · 权限阻断 | 系统授权；仍允许停止；不是自动清除开关 |
| 仅某来源撤销 | 某来源不再获准 | 更新来源清单；不把单源 -41 当作全局权限撤销 |
| 授权允许但零来源 | 还没有选择应用来源 | 提醒选择来源；当前 StartRelay 不以数量硬阻断，不假称已有消息 |
| 基础构建 | 当前构建不支持通知订阅 | 说明需要通知模式构建；不能伪弹通知授权 |
| 非适配手表 | 这台手表暂未适配 | 可识别候选，转发不可用；保留其他设备已存材料 |
| 账号 -12 | 网页登录完成，设备同步未完成 | 日志路线 / 重试；技术阶段放可展开详情 |
| 导入等待 | 正在读取与识别 | 无百分比；提供可取消入口 |
| 导入取消 | 本次导入已取消 | 不按失败染红；清理暂存候选，保留已存材料 |
| 导入错误 / 超时 | 日志未能读取 / 处理超时 | 保留已存材料，解释格式与限额并给重试 |
| 导入解析成功 | 已识别记录，待确认保存 | 用户确认自己的候选记录；解析成功不是已保存 |
| 收包成功 | 固定测试报文已收包 | 人工确认显示 / 执行；不能标为送达 |
| 人工未看到 | 报文已收包，未确认显示 | 保留传输证据并继续排查 |
| 诊断与转发冲突 | 通知转发开启，诊断暂不可用 | 用户明确停止后再进入诊断，不自动暂停或恢复 |

错误优先呈现一个相关、可恢复的问题；原始错误字符串不直接渲染。201 可能来自权限或设备能力，不能只归因于某一种。1600023 对应未启用通知订阅构建。-41 必须结合重新读取的权限快照区别全局和单来源。

## 视觉基线

延续原页面的青绿与墨色方向，降低诊断视觉噪声。浅色使用稳定白表面与淡灰绿页面底；深色用墨绿灰表面。主行动与选中状态使用青绿，成功、警告和失败各有文字，颜色不能单独表达含义。

design-tokens.json 是颜色、间距、字体、圆角、动效与布局建议的唯一语义来源。HTML 内嵌同值以实现单文件离线运行；后续生成 CSS 与 ArkUI 颜色资源时保留同名角色。

| 角色 | 建议值与使用 |
| --- | --- |
| 正文 / 次正文 / 辅助 | 16 / 14 / 12；Web 用 rem，原生按 fp 与系统字体比例 |
| 页面 / 区块 / 强展示 | 28 / 18 / 28；窄窗不把页面标题做成营销大字 |
| 留白 | 4 / 8 / 12 / 16 / 24 / 32 的节奏 |
| 圆角 | 12 小元素、16 行/内组、24 大表面、胶囊行动 |
| 操作目标 | 本项目 Web 最小 48 CSS px；原生按系统控件与平台尺寸验证 |
| 窗口策略 | ≤760：底部三项导航与单列；761–1090：侧导航与单列；≥1091：内容双列 |
| 动效 | 按下即时、局部反馈 180ms；未知进度只用活动指示，不伪造百分比 |

图标均为自绘统一描边 SVG；手表形状只是装饰，不冒充目标固件的真实通知画面。没有虚构系统状态栏、电量、信号或健康指标。

## 组件与行为

按钮：同一决策组只有一个主行动；提交中禁用重复提交，成功须由后台确认。停止转发有独立高优先级通路，不能因别的前台读取或发送占用而永远失效。

设备行：身份由不透明引用选择，显示名只用于阅读。候选筛选不等于协议适配；扫描使旧临时引用失效，保存前后台再次校验配对与材料绑定。

系统授权：使用系统提供的列表与返回结果；当前没有独立应用内 allowlist。系统页面取消保持旧确认快照并标记是否陈旧；查询失败不以“0 个应用 / 未授权”替代未知。

导入：后台拥有日志、候选密钥与取消句柄；页面只持有 CandidateRef 和安全标签。取消、返回或析构清理未保存候选；重新导入失败不删除已经保存的材料。

确认：删除材料、停订阅、切换设备前停转发、修改手表通知类别都先说清实际作用。确认取消保留现有状态。关闭转发不说“撤销已显示通知”。

诊断：开关开启时禁用诊断动作；若用户同意停止，需要后台确认停止，再取得独占通道。诊断结束保持停止。固定提醒与震动分别确认执行结果；仅检查协议版本不报告已认证。

反馈：错误用持久结果区域与恢复行动；简短信息用单个状态播报，不堆叠 Toast。一次操作的 ACK、人工确认和长期能力证据各自保留范围。

## 跨窗口、大字与无障碍

使用可用窗口宽度决定布局，不以设备名称硬编码。宽窗展示准备状态与摘要，不简单放大一条手机列；窄窗维持单列、正文换行和底部导航。状态、选中项和输入不会因窗口尺寸变化重置。

HTML 支持 125% 原型文字缩放；320/360/390 CSS px 下优先单列，隐藏纯装饰手表而保留全部信息。原生必须额外验收更高系统字号、横屏/分屏、输入法及安全避让。页面与弹层不设置固定正文高度；长错误可滚动，不裁切主行动。

语义 HTML 包括真实按钮、radio/checkbox、dialog、导航当前页、步骤当前项、持久标签、跳转主内容、可见焦点、状态播报。dialog 支持 Esc，关闭后焦点回触发者；选择器与控件键盘可达。状态文字加颜色，重要文字与主行动目标对比度 ≥4.5:1（静态令牌计算见验收报告）。

减少动态偏好下关闭旋转和过渡。原生使用系统控件反馈，TalkBack 类浏览器工具与鸿蒙屏幕朗读不能互相替代，原生无障碍仍需设备验收。

## 后续 ArkUI V1 生产接入顺序

1. 原生只建立 UI façade 与安全快照映射，保持现有通知修复；提取 Index 中的平台动作，页面不再持有 DeviceCredential 或 authKey。
2. 用 V1 单根状态所有者持有显式 ViewState class。后台事件映射后整体替换新快照，避免 @Builder 参数导致统计数字不更新。不迁移 V2。
3. 建立今日 / 设备 / 通知三页及独立引导与诊断路由。优先复用项目已用的 Scroll、Column、Row、Button、Text、Web；Tabs 或 Navigation 的具体签名先查本地 API 26 SDK，不凭 HTML 写法推断。
4. 接入授权完整快照、存储结果、配对重校验、取消与错误映射。开关由确认的 RelayConfig 改变，消息会话状态由真实事件改变。
5. 诊断与转发使用同一后台所有权仲裁，保持当前读配置防冲突，之后再抽单一连接拥有者；本次设计不改协议或后台。
6. 将颜色令牌生成 base / dark 资源，映射 vp/fp、系统安全区、生命周期和辅助功能语义。页面离开取消前台导入/诊断和账号暂存，不自动关闭已开启的通知后台。
7. 在 API 26 目标环境验收完整状态矩阵和系统字号；再按原项目计划验收手机通知 → 手表可见链路。
8. 后续音乐、健康与资源以 FeatureEvidence 与真实实现共同解锁，每项独立申请权限、确认目标支持与真机证据。

本轮仅确认 API 26 原生源代码编译通过。独立预览的任何 mock 状态都不能代替实际服务与通知链路验收。
