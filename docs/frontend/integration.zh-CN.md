# 原生界面接入记录

当前界面与使用流程以[通知功能界面与使用流程](notification-focused.zh-CN.md)为准。以下保留首轮接入记录；三页导航已经撤下。

2026-10-07 将独立设计成果接入主工程，使用现有 ArkUI V1、API 26 与手机本地签名。目录中 design-baseline、design-tokens、viewmodel-contract 文件保留设计交付时的原文；其中“尚未接入”的说明属于设计阶段，实际接入以本文件与源码为准。

## 页面与服务边界

- `Index.ets` 实现“今日 / 设备 / 通知”、四步初始化、诊断和官方账号登录页。采用语义配色资源、深色资源、系统字体缩放与可滚动内容。
- `AppState.ets` 只提供安全页面快照与动作；没有 AuthKey、账号 Cookie、通知正文或设备原始地址。候选使用临时引用，页面不管理认证材料。
- `AppViewModel.ets` 调用真实配对查询、系统通知授权、日志导入、安全存储、账号同步、转发及诊断服务。导航、取消与销毁会使旧异步结果失效，并清理暂存候选。
- 已选择设备的系统引用保留在应用私有目录，恢复时重新核对配对；转发配置仍由原有后台读取。认证材料仍由手机安全存储管理。

通知授权卡片在标题之后首先显示“管理系统通知授权”按钮，仅保留授权状态与来源数量，不展开全部应用。应用开关由系统授权页面管理。此调整以主工程为准，历史 HTML 原型仍用于设计讨论。

## 状态约束

转发开关表示用户意图，不代表常驻在线。授权查询失败显示未知并保留上次已确认来源；累计收包不代表手表显示。固定提醒、震动的人工确认仅记录本次诊断。停止操作读取后台活动标记，等待会话清理后才报告关闭；活动标记不是完整的跨进程通道租约，后续统一连接服务仍需完善。

原设计的 TypeScript 契约用于后续服务拆分，不是本轮逐项实现的运行协议。本轮使用 `AppCommand`、快照版本和操作代次，没有实现通用 requestId 去重总线或完整跨进程连接仲裁。健康、音乐和资源功能保留接口与计划入口，目前没有采集或可用操作。

## 验证

核心测试 45 项通过，含安全快照隔离与权限未知、转发意图、会话活动、收包证据相互独立的检查。通知模式原生编译和签名通过。账号同步、跨应用图标读取、手表图标显示及锁屏后台稳定性仍需实际验收；构建成功不能替代这些结果。
