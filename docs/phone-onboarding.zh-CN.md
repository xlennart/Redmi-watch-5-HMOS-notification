# 手机端初始化与认证材料

最终使用流程必须完全在手机上完成：选择手环或手表、获取认证材料、授权通知、连接与认证、发送测试提醒、日常转发、重新导入或删除认证材料。电脑、Python、ADB/HDC、桌面扫码页面和手动改源码不能成为最终用户的使用前提。电脑签名与调试只属于开发过程。

## 当前实现

“从手机日志导入”通过系统文件选择器读取用户选中的 ZIP、LOG 或 TXT，不申请读取整个存储空间。ZIP 只读取 `XiaomiFit.device.log`、`XiaomiFit.main.log` 及其备份，限制文件大小与总展开大小并校验 CRC；不把原文件和日志正文复制到应用文件目录。

识别 Redmi Watch 5 设备记录的 `detail.encrypt_key` / `encryptKey`，忽略账号 Cookie 的 `auth_key`。页面仅显示设备名称和地址末尾，用户选择后才保存该记录。保存使用鸿蒙 AssetStore，设置首次解锁后可访问、禁止同步，支持删除。首次解锁后的访问策略用于后续锁屏转发，仍需单独验证。

当前导入不会进行蓝牙消息通道认证，不代表已经能够发送手表通知。脱敏地址保留其后缀，不猜测完整地址；后续连接必须明确匹配设备。系统虚拟蓝牙标识也不能当作实际 MAC 地址。

候选设备覆盖各品牌手环与手表；认证当前仅适配非 Active/Lite、非 eSIM 的 Redmi Watch 5。这是两个不同阶段。

## 手机日志路线

1. 在卓易通打开已绑定手表的小米运动健康。
2. 打开“我的 → 关于”，连续点橙色应用图标，确认导出日志。
3. 将 ZIP 保存或分享到鸿蒙手机文件管理，再回到腕间通知选取。
4. 确认本人的设备记录并保存；页面不显示 AuthKey。
5. 原始日志仍由用户管理，导入不会删除原文件。

步骤 2 参考[米坛的 OronBox 教程](https://wiki.bandbbs.cn/Guides/oronbox/oronbox-install.html)。卓易通能否把文件导出给鸿蒙原生应用仍需真机验证。若无法导出，不能要求接电脑绕过；应由应用内账号同步完成初始化。

## 账号同步路线

[AstroBox 连接教程](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-connect.html)和 [OronBox 源码](https://github.com/zxor-org/OronBox)提供手机端登录与导入设备的参考，不代表已有原生鸿蒙适配。

运动健康使用 `miothealth` 服务，设备列表参考端点为 `https://hlth.io.mi.com/app/v1/source/get_source_list`；不是米家 `xiaomiio` 的设备 Token 接口。账号同步需在手机处理登录、官方二次验证、服务会话和加密请求。米家 BeaconKey 提取器不能作为已验证的替代实现。

已增加原生应用内的小米官方登录页，使用临时浏览会话；密码与验证码由用户输入。点击“登录后同步设备”调用运动健康服务并列出目标设备记录，用户确认后才保存认证材料。完成同步或返回时清理浏览会话，不保存账号令牌。

2026-10-06 手机实测：用户确认日志导入的认证材料已保存；官方网页登录能够完成，但获取运动健康服务会话失败。当前修复在隐藏的同一浏览会话中读取服务响应正文与 `Extension-Pragma` 响应头，区分登录挑战、缺少安全参数、交换地址异常和请求超时；凭据响应不展示。账号同步不调用卓易通或小米运动健康应用，实际成功仍需复测。若本轮仍失败，保留日志路线继续蓝牙认证与转发，不把账号同步作为阻塞前提。

不自动解绑、重置手表或切换“连接新手机”，这些操作可能改变当前绑定及认证材料，实际需要时应说明影响并由用户操作。

## 最终验收

- 新安装后，仅凭手机取得有效 AuthKey；卓易通无法导出时，也有可用的手机端替代路线。
- 可以处理验证码、目标设备选择、失败重试和过期会话。
- 认证材料不进入界面、剪贴板、日志、Git、备份同步或诊断回传，可从手机删除并重新获取。
- 手机重启并首次解锁后，锁屏通知仍能送达手表；认证失败不会显示为连接成功。
- 不要求电脑命令、手动复制密钥或默认重新绑定。
