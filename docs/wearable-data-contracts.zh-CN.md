# 睡眠与运动数据扩展接口

当前仅预留接口，不查询、保存或展示健康数据，不增加相关权限或页面。

接口定义在 `entry/src/main/ets/core/WearableData.ets`。未来设备适配器实现 `WearableDataProvider`，把设备协议映射为睡眠、每日运动与单次运动记录。展示层和本地数据层依赖统一模型，不依赖某款手表的 protobuf 字段、小米账号接口或蓝牙报文。

| 接口 | 职责 |
| --- | --- |
| `capabilities()` | 区分未知、不支持、可用和待授权，通知可用不代表睡眠可用 |
| `readSleep(query)` | 查询睡眠时段、阶段及小睡标记 |
| `readActivity(query)` | 查询按当地日期汇总的步数、距离、活动时长和活动能量 |
| `readWorkouts(query)` | 查询单次运动的时间、项目及可选测量值 |
| `cancelPendingReads()` | 设备切换、页面退出或主动取消时停止读请求 |
| `WearableDataRepository` | 独立持久化、查询及按设备删除，不混入 AuthKey 或通知计数 |

时间统一使用 Unix 毫秒和左闭右开的区间 `[fromInclusiveMs, toExclusiveMs)`。睡眠支持跨午夜时段；每日汇总保留当地 `YYYY-MM-DD` 和当时 UTC 偏移。距离单位为米、时长为分钟、能量为 kcal。缺失字段保持 `undefined`，睡眠阶段可为 `UNKNOWN`，不能把未知值补零或推算成测量结果。

分页通过 `pageSize` 和不透明 `cursor` 控制，`complete` 只有在完整读取所请求时间范围后才能置为 true。实现需检查时间范围、页大小、睡眠阶段覆盖与重叠；中断和部分结果不能冒充完整同步。错误码区分不支持、未授权、断开、取消、非法范围、非法数据及存储不可用。

每条记录保留适配器 ID、应用分配的稳定设备 ID、设备记录时间与导入时间。去重键为“稳定设备 ID + 适配器 ID + 记录 ID”；更新同一记录应执行 upsert。系统蓝牙虚拟标识可能变化，不作为长期健康记录的设备身份。展示层只显示用户选择的设备名称，不暴露 MAC 或密钥。

后续实现顺序：确认目标固件的数据读取能力 → 实现设备适配器和统一映射 → 建立独立数据存储 → 接入展示。届时由用户启用同步范围与删除方式；当前账号同步只获取设备认证材料，不扩展为读取账号内运动健康数据。
