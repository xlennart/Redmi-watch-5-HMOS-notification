# 0.1.2：页面切换、留白与状态刷新修复

2026-10-13 用户反馈：音乐页内容出现在通知选中状态下，无法返回通知内容；页面顶部和底部留白过多。已在连接的真实手机复现：点击音乐后，再点击通知，布局仍停留在音乐内容。

根因是 ArkUI V1 局部 Builder 的按值参数。导航的 `selected` 保存首次构建值，点击事件用这个旧值判断是否切页；同类按值参数也会让异步授权后按钮可用状态、文字、统计或折叠提示停留在初始值。本轮不引入新的视觉方案或状态管理版本。

修复采用当前路线实时判定导航点击，导航样式直接读取状态；动态 Builder 改为单一 `$$` 引用参数，保留原命令与 ViewModel。通知、音乐、设置内容仍由真实 route 决定，不使用样例数据或定时器伪造状态。

顶部改用单行主要页面标题，减少字号、标题尾距和内容内边距；顶栏 52 vp、底部导航 56 vp。Scroll 显式顶部对齐，避免短内容在视口中垂直居中。短页面剩余的自然空间不靠假内容填充。

根据华为官方[安全区域规范](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-universal-attributes-expand-safe-area)，主页面和账号登录页面的根容器通过 `expandSafeArea` 仅扩展上下系统安全区的绘制，不改变内容布局。主窗口使用与页面资源一致的底色，状态栏和导航栏透明、内容深色；状态栏、手势条继续显示，标题与导航按钮保留系统避让，不使用固定状态栏高度或负边距。键盘避让不扩展、不关闭。修复截图中的上下白色条带，背景贯通到屏幕边缘。

原生音量面板只在音乐页开启音乐控制时显示，其他页面不占用 48 vp 空间；音量桥同步检查面板实际所在路线，未显示面板时明确报 -66，不能把没有执行的音量变化当作成功。播放、暂停和切歌仍沿用原媒体会话控制。

工程完整性检查通过，89 项回归通过，API 26 通知加音乐模式 clean 编译签名成功。已覆盖安装到真实手机，检查通知 → 音乐 → 通知、通知 → 设置 → 通知：内容正确返回，音乐页高亮与正文一致，通知授权摘要和测试按钮异步状态刷新正确。真实截图确认主页面和音乐页的状态栏、手势区与页面背景连续，标题与导航按钮边界保持原安全区坐标。账号登录页使用同样绘制设置，未重新登录；横屏、分屏、大字体和账号键盘尚未单独实测。原始布局和截图只存本机忽略目录，不上传包含设备名或其他状态栏信息的图片。
