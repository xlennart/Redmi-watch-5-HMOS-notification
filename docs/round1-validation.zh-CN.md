# 第一轮云端交付与验证记录

日期：2026-10-06。分支：`codex/round1-notification-probe`。本文件随交付提交保存，具体版本以 `git rev-parse HEAD` 为准。

## 交付范围

- API 26 Stage 工程，包名 `com.xlennart.wristnotifications`，暂定名称「腕间通知」。
- 原生 ArkUI 首页：设备、授权、接收三卡，处理中/错误反馈及折叠诊断信息。
- 动态读取系统已配对设备与 HFP 连接，选择只保存在当前会话，不保存真实/虚拟 MAC。
- 通知模式声明 `notificationSubscriber` 扩展，调用设备关联、API 26 授权弹窗、状态查询及取消订阅接口。
- 扩展接收/取消回调立即保存元数据；只由扩展写入，页面读取，不假设 UI 和扩展同进程常驻。
- 默认基础模式不声明受限通知权限。模式切换同时生成清单和 UI 标记，避免二者不一致。
- 共享 `.ets` 核心、锁定 npm 依赖、11 项测试、GitHub Actions 和本地操作指南。

## 云端鸿蒙环境配置的性价比

本轮已在 `/tmp` 隔离安装官方 `@deveco/deveco-cli@1.3.0-stable`，可读取模板和随包 API 文档；CLI 启动尝试因默认日志路径位于当前不可写目录而失败。没有取得可用的完整鸿蒙构建环境，不把“安装了 CLI”作为编译证据。

当前云端网络仅允许配置过的依赖/GitHub 站点；华为 SDK、OHPM 与签名服务所需站点不在已确认的允许范围。完整安装还需要平台匹配的工具、持久化 SDK 缓存、许可与账号条件。暂时不为第一轮重建一套完整环境：权限和蓝牙仍须真机验证，云端全量环境不能代替本机角色。

若本地往返的主要成本变成 ArkTS 编译错误，增加无签名编译预检才更有价值。届时在正常允许的网络和持久化环境中，固定与本地相同的 Command Line Tools/SDK，先确认普通模式可构建，再加云编译 CI。证书、ACL Profile 与手表 AuthKey 继续保留本地。详细比较见 [实施方案第 18 节](implementation-plan.zh-CN.md#18-在云端再次配置鸿蒙开发环境的性价比)。

## 第一轮本地优先顺序

1. 拉取此分支，执行核心检查，在 IDE 中编译并安装基础模式，检查页面与配对查询。
2. 确认华为账号和 Profile 能获得通知 ACL；若受阻，先回传具体资格/签名问题。
3. 切换通知模式，验证前台、锁屏后台、取消和撤销授权。
4. 把脱敏结果和 commit 发回云端，修复同一分支，再开始手表协议工作。
