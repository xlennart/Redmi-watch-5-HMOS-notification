# 手机音乐控制与本轮验收

## 当前范围

2026-10-12 按用户要求新增手机播放状态同步和手表遥控，不涉及把歌曲上传到手表。通知仍为首页；音乐页面是“设置 → 手机音乐控制”的次级入口，健康、运动、音乐库、账号及其他设备功能不扩展。既有通知界面设计继续适用于首页，本页优先于历史文档里“音乐只保留接口”的描述。

## 实现

- `PhoneMediaAdapter.ets` 通过 API 23+ 的 AVSession 公共控制器枚举媒体会话，选择系统置顶的活动会话；排除本应用及不活动的历史记录。监听媒体会话、元数据、播放态变化，每秒读取当前状态，进度使用系统实时播放位置。无活动会话、停止或撤权不会沿用上一首标题。
- `WatchMusic.ets` 独立编写 Xiaomi `18/1` 状态与 `18/2` 控制编解码。同步标题、艺术家、播放/暂停/空闲、秒数和音量；接收播放、暂停、上一首、下一首及音量目标。平台先检查播放器开放的控制命令；音量目标与当前百分比比较后只增减一个原生档位。协议证据见[专项核对](music-protocol-research.zh-CN.md)。
- `WatchNotificationRelay` 在开启音乐时保持已认证 SPP v3 连接；通知复用同一会话，所有发送仍串行等待 ACK。关闭音乐恢复原有逐条通知连接方式。初始化连接失败会回滚音乐开关；运行中断每三秒尝试恢复通道，失败的通知不重发。媒体服务调用有三秒超时，关闭后晚到控制器释放而不执行操作。
- 手表控制只接受认证后的加密应用帧；相邻重复帧不重复执行。图标协商或通知配置回应期间到达的音乐事件进入有上限的内存队列，结束后继续处理。通知/图标占用通道时控制可能延迟，不保证并行传输。
- 音乐使用 Bluetooth 持续任务，系统会显示任务通知。活动标记有时间戳，进程结束后旧标记过期，旧累计收包不能代表当前在线。连接协调器在同一应用进程内共享；不是跨进程租约或重启后自动恢复服务。

页面不展示伪造曲目或成功态。仅展示真实连接阶段、状态收包计数、手机接受控制的计数以及数值错误码。标题、艺术家、媒体会话 ID 和播放 URL 不写磁盘或诊断日志。音乐状态传输 ACK 不等于手表显示，系统接受控制不等于实际切歌或开始播放。

## 构建与权限

默认 `npm run configure:baseline` 保留基础模式；`npm run configure:notifications` 保留已有通知权限范围；`npm run configure:music` 生成通知加音乐模式，注册 Bluetooth 持续任务并增加：

| 权限 | 本机 API 26 定义 | 使用方式 |
| --- | --- | --- |
| `MANAGE_MEDIA_RESOURCES_FOR_PUBLIC` | system_basic、system_grant、ACL 可配置 | 必须包含在官方签名 profile 的 allowed-acls 中，运行时检查 access token；不使用用户弹窗申请 |
| `KEEP_BACKGROUND_RUNNING` | normal、system_grant | Bluetooth 持续任务 |
| `ACCESS_NOTIFICATION_POLICY` | normal、system_grant | SDK 旧式全局媒体音量设置接口所需权限；不调整铃声或勿扰模式 |

定义以目标 SDK `toolchains/lib/PermissionDefinitions.json` 与对应 API 声明为准。API 指引见华为[媒体控制器](https://developer.huawei.com/consumer/en/doc/harmonyos-references/arkts-apis-avsession-avsessioncontroller)与[音量管理](https://developer.huawei.com/consumer/en/doc/harmonyos-references/arkts-apis-audio-audiovolumegroupmanager)。编译成功不表示设备授予权限。

本机已由官方 DevEco CLI 生成包含通知和媒体会话两项 ACL 的 profile，沿用原密钥库、别名和证书。材料不上传；其他开发者须独立申请签名。CLI 若在自动化进程因代理出现 TLS 主机名不匹配，应检查该进程的代理变量；本轮通过仅对该进程直连解决，未关闭 TLS 校验或改动系统代理。

## 本轮证据

- 共享核心及原生平台适配 mock 共 68 项测试通过：协议字段、UTF-8、边界值、未知命令、媒体会话选取、控制支持过滤、关闭与晚到回调、加密路由、图标期间事件保留、取消唤醒等。
- DevEco / CLT 26.0.0.851、API 26 原生编译、签名与 `hdc install -r` 覆盖安装成功。
- 安装后未自动操作手机页面；手表图标渲染、播放/暂停/切歌/音量、后台与锁屏、断线恢复尚未验收。卓易通内 Android 播放器能否向鸿蒙媒体中心开放会话也未验证。

## 手机测试

1. 打开腕间通知，确认原有手表与认证材料仍在；开启通知转发，让一个已授权的原生手机应用发送新通知，检查手表通知文字及该应用图标。不要用此前已缓存的旧通知判断新图标。
2. 在手机音乐或视频应用开始播放，打开腕间通知“设置 → 手机音乐控制 → 开启音乐控制”。手表打开手机音乐控制页面，依次测试暂停、播放、上一首、下一首及音量。确认两端实际播放状态，不仅看累计计数。
3. 音乐控制开启时再发送一条真实通知，验证通知仍到达；然后锁屏复测。若失败，反馈本页连接状态、最近错误码及手机接受控制是否增加，不发送曲目隐私、认证密钥或账号令牌。

关闭通知转发、切换手表、删除认证材料或诊断测试会同时释放音乐连接，需要手动重新开启音乐。仅关闭音乐则保留通知设置。无需解绑、重置手表或删除小米运动健康绑定。
