# 离线通知应用图标

2026-10-13 按用户要求尝试在线图标来源，统计体积后改为随应用保存离线图库。资源来自 [sooyaaabo/IconLibrary](https://github.com/sooyaaabo/IconLibrary) 的 App 目录，393 张 PNG 合计 11995983 字节，约 11.44 MiB；不是 393 个独立应用，部分是同一应用的不同版本。微信、QQ、支付宝三个文件共 87377 字节，约 85.3 KiB。

资源保存在 `entry/src/main/resources/rawfile/notification-icons/`。`catalog.json` 固定上游 tree 标识、每个文件长度和 SHA-256；下载时逐一比对上游 Git blob SHA-1。原始 MIT 许可放在同目录 `LICENSE.txt`，保留作者声明。项目仅为通知来源识别使用这些网络整理的图标，不表示获得品牌方背书，也不声称各平台应用的实时图标始终一致。

## 数据路径和资源占用

1. 通知转发层仍只处理系统已授权来源；命中精确包名映射后，通过本应用 ResourceManager 读取对应 rawfile，不再调用其他应用包信息查询。
2. 在解码前检查 PNG 签名、IHDR、512 KiB 文件上限及最大 1024 像素边长。图库中的一个桌面图标 `Tampermonkey.png` 为 2048 像素，未映射；手机解码器会拒绝它，后续需提供更小版本才能使用。
3. 原生解码并转换 BGRA，复用现有预乘透明度处理、保留宽高比缩放、176 像素格式协商及 MASS 分片路径。
4. 每次只解码当前图标；不把 393 张图同时读入内存。最大解码像素缓冲约 4 MiB，常用图标更小；传输数据最多 256 KiB，处理结束后清零字节并释放 PixelMap/ImageSource。
5. 正常运行不访问图标服务器，不上传来源包名或通知内容。未映射来源尝试原有原生资源路径；不可访问时继续文字通知并保留默认图标。

`offline_transport_ack` 表示离线图标分片被手表确认，不等于实际显示成功；手表报告 `cached` 时也要检查新的通知。自身测试图标此前已由用户确认显示，不能替代其他来源的验收。

## 验证

核心和平台 mock 共 81 项测试通过，包含完整资源清单/长度/摘要检查、精确包名与恶意路径拒绝、解码前 PNG 尺寸限制、跨应用权限被拒绝时的离线加载、缓冲清理与传输来源标记。原生编译、签名、手机安装及手表可见效果分别记录，Node 测试不替代真机验收。

本轮 API 26 原生编译与原有调试签名已通过，包含完整图库的签名 HAP 为 12876049 字节，约 12.28 MiB。恢复手机调试连接后，临时诊断包在真机逐一加载微信、QQ、支付宝的内置 PNG，三项均转换为 176×176 BGRA，每项 123904 字节，合计 371712 字节；只保存检查数、成功数与字节数，不记录图像或通知数据。随后覆盖安装并启动正式包，临时诊断代码未进入 Git 或正式 HAP。该结果证明原生离线资源读取与转换成功，手表可见图标仍待新的真实来源通知确认。签名材料和 HAP 保留本地忽略目录。

测试时重新开启通知转发，让上述已授权应用产生一条新的普通通知；不需要产生支付交易。对照手表通知文字和图标；华为支付仍默认图标属于本轮未覆盖范围。安装或诊断后如音乐连接显示未知，手动重新连接；后台音量限制保持原有结论。
