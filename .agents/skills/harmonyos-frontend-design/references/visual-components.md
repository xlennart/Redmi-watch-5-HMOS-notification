# 视觉基线与组件决策

## 视觉结构

首先复用已有设计语言；新项目可使用 assets/design-tokens.json 的默认配置。它是一套可执行的项目起点，不是华为官方规格副本。

将界面拆成页面底、内容表面、互动层、浮层四类。内容卡片依靠留白和表面色形成分组；菜单、导航或半模态需要体现叠放关系时才使用轻阴影或模糊。密集正文区保持稳定可读，不因强调“光感”而普遍透明化。

品牌色用于核心行动和选中状态；成功、警告、失败使用独立语义，并同时提供文案或图标。不要以华为品牌红替代用户产品的品牌色。图标采用现有图库和一致的视觉粗细；原生场景优先现有系统符号资源，Web 场景复用许可明确的图标。不要把系统品牌资产视为自由素材。

## 推荐默认令牌

| 类别 | 示例配置 | 使用方法 |
|---|---|---|
| 操作色 | 浅色 #0A59F7，深色 #83B3FF | 主按钮、链接、选中态；按钮文字单独采用 on_action |
| 字体 | 12 / 14 / 16 / 18 / 22 / 28 | 辅助、次正文、正文、区块、页面、展示标题；Web 用 rem，ArkUI 跟随项目 fp 规则 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 形成稳定节奏；参考稿或官方控件有明确值时遵循其值 |
| 圆角 | 8 / 12 / 20 / 胶囊 | 输入/小元素、普通内容、较大表面、行动控件 |
| 页面留白 | 窄窗 16，宽窗 24 | 内容留白和系统避让区域独立计算 |
| 示例断点 | 600 / 840 CSS px | 本示例的窗口策略；不可当成 ArkUI 默认断点或硬编码设备类型 |
| 动效 | 100 / 180 / 260 ms | 微反馈/局部变化/较大过渡的项目起点；按距离、频率和目标设备调整 |

Web CSS px、rem 与 ArkUI vp、fp 是不同环境的度量。按角色迁移数值，不宣称一一等价。窄屏中文页面标题优先 22 或 28，营销大标题按产品需求另设。

## 组件配方

| 组件 | 视觉与结构 | 必须处理的行为 |
|---|---|---|
| 主/次按钮 | 操作色或低强调表面；同一决策组分清主次 | 按下、焦点、禁用、提交中；防重复提交；请求完成才确认结果 |
| 卡片/列表 | 内容对齐、合理分组；整行可点与行内操作避免冲突 | 長文换行、空列表、滚动、辅助工具可读；点击目标明确 |
| 表单/输入 | 持久标签、输入区、帮助/错误文案；占位符不能代替标签 | 校验时机、清除、软键盘遮挡、错误后保留数据 |
| 开关/选择 | 开关表达立即生效的二元偏好；单选/多选语义各自明确 | 状态不依赖颜色；远端保存可能失败时回滚或提示 |
| 顶栏/导航 | 页面名与返回路径可理解；稳定定位当前页 | 滚动避让、返回、焦点顺序；宽窗可转为侧导航/分栏 |
| Tabs/分段控件 | 相互排斥的视图切换，选中状态清晰 | 语义标签、方向键/焦点；若没有切换面板，用普通选项按钮组 |
| 菜单/弹窗/半模态 | 浮层与触发者有关系，内容与风险明确 | ESC/取消、焦点约束与返回触发者；不以 Toast 承载需处理的错误 |
| Toast/状态反馈 | 简短、不遮核心操作；正文可持久展示重要错误 | 使用状态播报；重复操作不能堆叠不可读提示 |
| 进度/加载 | 明确区分未知时长与已知进度 | 未知时长不伪造百分比；取消/失败/重试按真实业务实现 |
| 空/错误/引导 | 解释现状并给出可行下一步 | 已输入内容不丢失；避免把权限未授予描述成系统成功 |

原生优先系统 Button、TextInput、Toggle、Radio、Checkbox、List、Navigation 等。Web 采用 button、input、fieldset、dialog 等语义控件模拟体验；系统状态栏不属于一般网页必备内容，不虚构电量、网络或分布式流转能力。

## 跨窗口策略

- 紧凑窗：保证主要任务、关键操作和滚动通路；输入时避开软键盘。
- 中等窗：扩展内容列数，避免将表单和长正文横向无限拉伸。
- 宽窗：列表与详情或内容与辅助信息分栏；状态共享，窗口变化不清空输入。
- 折叠和多窗口：以可用空间、折痕/避让区域和实际平台能力决定布局；宽度变化不等于折叠状态变化。
- 穿戴、电视、座舱：先选择对应官方设备指南；本示例默认令牌不直接扩展为这些设备的规格。

## 导出令牌

在技能目录运行（Python 3 标准库，无第三方依赖）：

```powershell
python scripts/export_tokens.py --target css --out examples/tokens.css
python scripts/export_tokens.py --target arkui-colors --out <独立输出目录>
```

第二条生成 base/element/color.json 与 dark/element/color.json，资源名形如 harmony_action。对已有项目先核对同名资源，再按实际需求合并；不要直接覆盖整个资源文件。输出值会将 Web #RRGGBBAA 转为 ArkUI #AARRGGBB。主题策略应交由项目现有资源体系管理。
