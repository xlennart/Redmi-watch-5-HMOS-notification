# ArkUI 落地、状态与动效

## 开始实现前

从工程配置和邻近页面确认 SDK/API、设备范围、V1/V2 状态模型、导航入口、资源命名及组件封装。沿用既有写法。没有工程时，可交付说明清楚的组件片段；不要把一个无工程片段描述为已编译的 HAP。

原生页面的字体、颜色和尺寸优先使用项目资源。系统资源和平台控件优先于手写仿制。引入新 Kit、API 或装饰器时核对官方文档中版本、导入方式、支持设备和限制；不要凭 Web 或 TypeScript 经验推断 ArkTS 的语法支持。

| 需求 | 候选 ArkUI 能力 | 核对点 |
|---|---|---|
| 多列响应布局 | GridRow / GridCol、项目断点封装 | 显式阈值和默认断点分清；参考目标 SDK |
| 列表/详情与返回 | Navigation / NavDestination | 复用导航栈；窗口改变保持选中与滚动状态 |
| 控件状态 | 项目 V1 或 V2 状态装饰器 | 不为单页改动批量迁移；数组/对象更新遵循所用模型 |
| 输入与避让 | 现有窗口/安全区/键盘适配封装 | 无条件扩展安全区可能遮住关键操作 |
| 多属性同参数变化 | animateTo 或 UIContext 对应 API | UI 上下文、生命周期、动画完成回调的含义 |
| 出现/消失 | transition | 插入/删除结构和默认转场是否叠加 |
| 连续位移/缩放 | transform 类属性 | 避免逐帧修改布局造成重排 |
| 手势跟手/回稳 | responsiveSpringMotion / springMotion 等曲线 | 目标 API 支持、连续更新与速度行为需要实际验证 |
| 共享容器关系 | geometryTransition | 标识、生命周期、匹配结构和默认转场叠加 |
| 图标按钮语义 | Button 及 accessibilityText 等 | 有动作、可访问名称和足够触控区域；确切属性按 SDK 核对 |

表内是能力选择线索，不能替代对应版本的 API 签名。

## 异步状态

区分 Idle → Pending → Confirmed / Failed；按下反馈与业务完成分开。Pending 时阻止重复提交，给可理解的状态。真实业务 promise/callback 成功后再展示成功；失败保留可恢复内容并给重试。

乐观更新只在业务允许时使用，必须有失败回滚或同步状态。不把动画 onFinish 当请求结束，不用固定定时器伪装持久化完成。Demo 中的模拟必须明确标识，并展示成功与失败两条路径。

## 动效选择

- 小型颜色/透明度变化：短过渡，通常不需要弹跳。
- 元素进入：让用户理解来源和终点；退出与返回保持方向一致。
- 拖拽：跟手、可打断；释放时检查速度衔接、目标改变和边界。
- 多次快速操作：从当前状态继续，不跳回初始状态；防止旧回调覆盖新状态。
- 系统控件已有反馈时，先检查默认行为，避免叠加缩放和弹簧。
- 低运动模式：用更短的淡入/即时状态变化维持信息含义；可操作功能不能依赖动画。

物理曲线不是定长业务计时器。平台支持与实际手感由目标设备上的运行决定。手势或共享转场需要可交互验证，静态截图只能证明布局。

## 证据

代码检查能证明调用和状态关系；构建能证明目标工程编译；模拟器/设备能证明交互和适配。帧率、长帧、无障碍播报需要相应运行证据。只报告已取得的层级，不把一层证据扩大到另一层。
